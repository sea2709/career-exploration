# web/ — Career Explorer frontend

Astro 7 + React 19 chat UI that proxies to the career agent service in `../agent`. See `README.md` for setup and architecture.

## Development

When starting the dev server, use background mode:

```
astro dev --background
```

Manage the background server with `astro dev stop`, `astro dev status`, and `astro dev logs`.

The chat only works end to end when the agent service is also running (`cd ../agent && npm run dev`, port 8787) and `web/.env` has `AGENT_API_TOKEN` (matching `agent/.env`) plus Turnstile keys. Cloudflare's test keys in `.env.example` work for local dev.

Type-check with `npx astro check`. There is no test suite or lint script.

## Layout

- `src/pages/index.astro` mounts `CareerChat` with `client:only="react"`. There is no SSR of the chat UI.
- `src/components/CareerChat.tsx` uses `useChat` from `@ai-sdk/react` with a `DefaultChatTransport` pointed at `/api/chat`. It renders text parts with `react-markdown` and tool-call parts as chips.
- `src/components/HumanCheck.tsx` renders the Turnstile widget and posts the token to `/api/verify-human`.
- `src/lib/human-verification.ts` holds the Turnstile siteverify call and the HMAC-signed `human_session` cookie helpers.
- `src/pages/api/chat.ts` and `src/pages/api/verify-human.ts` are server routes (`export const prerender = false`).
- `Button.astro`, `layouts/main.astro`, and `pages/markdown-page.md` are leftovers from the Astro Tailwind starter and aren't used by the chat.
- `sanity.types.ts` is generated by `npm run typegen` in `../studio`. Never edit it by hand.

## Conventions and constraints

- **Env vars go through `astro:env`.** Declare new vars in the `env.schema` block of `astro.config.mjs` with `envField`, then import from `astro:env/server` or `astro:env/client`. Don't use `import.meta.env` or `process.env` for app config. Update `.env.example` whenever you add one.
- **Secrets stay server-side.** `AGENT_API_TOKEN` and `TURNSTILE_SECRET_KEY` are `access: 'secret'` and must only be read in server routes or `src/lib`. The browser must never call the agent directly; all chat traffic goes through `/api/chat`.
- **`/api/chat` is gated by the human session.** Any new API route that triggers agent or LLM work should also check `hasHumanSession(cookies, TURNSTILE_SECRET_KEY)` and return `403` when it fails. The client treats `403` as "re-verify".
- **Keep the proxy transparent.** `/api/chat` forwards the request body as-is and only passes through the headers in `PASSTHROUGH_HEADERS`, which the AI SDK needs for streaming. If the agent starts sending a new header the client depends on, add it there.
- **Tool labels live in `TOOL_LABELS`** in `CareerChat.tsx`. When the agent (`../agent/src`) adds or renames a tool, update this map so the chip shows a readable label.
- **Adapter is chosen at build time**: `@astrojs/vercel` when `VERCEL` is set, otherwise `@astrojs/node` in standalone mode. Keep server code compatible with both (Node APIs like `node:crypto` are fine).
- **Styling is Tailwind 4 utilities inline** in components. `src/styles/global.css` only imports Tailwind. There's no Tailwind config file; use `@theme` in `global.css` if design tokens are needed.
- Code style: tabs, single quotes, semicolons.

## Agent skills

`.agents/skills/` (symlinked into `.claude/skills/`) contains Sanity Context skills: `create-agent-with-sanity-context`, `shape-your-agent`, and `dial-your-context`. They mostly apply to the agent service in `../agent`, but consult them when changing how the chat UI surfaces Sanity-backed tool calls.
